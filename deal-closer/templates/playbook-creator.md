# Playbook Creator

> Build playbooks from your top performers, not from theory. What works in YOUR market, for YOUR product.

## The playbook loop

```
Observe top performer → Document the pattern → Test with others → Measure results → Skillify
```

## How to build a playbook

### Step 1 — Identify the pattern
Pick one specific behavior from a top performer:
- "She always quantifies pain in the first call"
- "He sends a 2-minute video instead of a 10-page deck"
- "They always ask about the decision process before pitching"

### Step 2 — Document the template
Write it as a skill file (one capability, one job):
```
# Skill: quantify-pain-first-call
Job: In the first discovery call, always ask 3 questions to quantify the prospect's pain:
1. "What happens if you do nothing for the next 6 months?"
2. "How many hours/week does [PAIN] consume?"
3. "What's the revenue impact of [PAIN]?"
Then: "So if I'm hearing you right, [PAIN] is costing you roughly [$X/Y] per [TIMEFRAME]. Is that right?"
```

### Step 3 — Test with the team
Give the template to 2-3 other reps. Run for 2 weeks. Track:
- Did they use it? (adoption)
- Did it improve outcomes? (effectiveness)
- Did they modify it? (adaptation = good)

### Step 4 — Measure and iterate
Compare:
- Before playbook: [METRIC]
- After playbook: [METRIC]
- Delta: [IMPROVEMENT]

### Step 5 — Skillify
If it works → add to the playbook library. If it doesn't → document why and try a variant.

## Playbook library (add yours)

### Playbook: First Discovery Call
1. Open with their context (research them first)
2. Ask: "What prompted you to take this meeting?"
3. Quantify pain (3 questions above)
4. Map decision process: "Walk me through how a decision like this gets made here"
5. Identify champion: "Who else on your team feels this pain?"
6. Close with clear next step

### Playbook: Enterprise (Fortune 500)
1. Always get a warm intro (never cold-email an EB directly)
2. Multi-thread: champion + economic buyer + technical evaluator
3. Map the procurement timeline (it's always longer than you think)
4. Build a business case in their language (ROI, risk reduction, compliance)
5. Prepare for security/legal review early (have docs ready)

### Playbook: Follow-Up Sequence
- Day 0: Thank you + next step recap
- Day 3: Additional value (case study, insight)
- Day 7: Check-in with question
- Day 14: "Last touch" + door open
- Day 30: Nurture (quarterly)

## Rules
- Every playbook must be tested (not just written)
- Every playbook must have a metric (before/after)
- Every playbook must be a skill file (reusable, not a one-off doc)
- If a pattern appears 3+ times across deals → it belongs in the playbook
